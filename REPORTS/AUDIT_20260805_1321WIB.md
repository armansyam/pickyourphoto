## 🔍 2. Verifikasi Arsitektur & Keamanan Kode Terinci

### A. Autentikasi & Verifikasi Sesi (`lib/auth.js`)
- **Fresh Database Lookup:** Setiap panggilan `getAuthVendor()` tidak hanya mempercayai muatan (*payload*) JWT, melainkan melakukan query ulang ke database:
  ```sql
  SELECT v.*, p.name as planName, p.allowCustomLogo, p.allowRawSelector 
  FROM vendors v LEFT JOIN plans p ON v.planId = p.id WHERE v.id = ?
  ```
- **Status Gatekeeper:** Akun dengan status non-`active` (`pending_payment`, `suspended`, `expired`) langsung ditolak pada baris 56 (`if (!freshUser || freshUser.status !== 'active') return null`), mencegah bypass hak akses.
- **Subsidi Proyek Dinamis:** Menghitung sisa kuota proyek tambahan secara *real-time* berdasarkan `additionalProjectsExpiresAt`.

### B. Otorisasi Pembatalan Sesi Pembayaran (`app/api/payment/cancel/route.js`)
- **Eliminasi IDOR Vulnerability:** Cabang otorisasi `vendorId` mentah dari request body telah dihapus.
- **Strict Boundary Check:** Poin otorisasi dipatok hanya pada 3 kondisi valid:
  1. Pengguna terautentikasi sebagai `admin`.
  2. Pengguna terautentikasi sebagai `vendor` pemilik sesi (`session.vendorId === currentUser.id`).
  3. Calon vendor (draft) yang membuktikan kepemilikan email yang terdaftar pada sesi tersebut.

### C. Webhook Notifikasi Midtrans (`app/api/payment/notification/route.js`)
- **Validasi Kriptografi SHA512:** Pesan webhook divalidasi menggunakan hash `SHA512(orderId + statusCode + grossAmount + ServerKey)` sebelum memperbarui database.
- **Transaksional Atomik:** Saat pembayaran terkonfirmasi (`settlement`/`capture`), status transaksi diubah ke `'paid'`, tanggal kedaluwarsa dihitung otomatis (`hari ini + activePeriodDays`), dan email konfirmasi SMTP terkirim secara asinkron.

### D. Eksekusi Auto-Backup Mandiri (`lib/db.js`)
- **Penjadwalan Otonom:** Logika eksekusi skrip `bash scripts/backup-db.sh` dan `bash scripts/backup-photos.sh` diletakkan di dalam `setInterval` daemon (60 detik) pada `lib/db.js`.
- **Independensi Halaman Web:** Eksekusi backup tidak lagi membutuhkan pemicu request HTTP dari Admin di halaman Analitik, melainkan berjalan murni di background proses Node.js.

## ⚠️ 4. Catatan Pemeliharaan & Technical Debt

1. **Kolom Legacy di Tabel `photos` (`watermarkedPath` & `fileSizeBytes`):**
   - Kolom `watermarkedPath` berisi string identik dengan `originalPath`.
   - Kolom `fileSizeBytes` bernilai `0` karena arsitektur Zero-Storage tidak menyimpan file fisik foto di disk server.
   - *Rekomendasi:* Kolom ini dibiarkan untuk backward compatibility dengan komponen frontend tanpa menimbulkan error runtime.

2. **Kebijakan Retensi Backup SQLite:**
   - Skrip `scripts/backup-db.sh` mengimplementasikan pembersihan otomatis berkas cadangan lama yang berusia lebih dari 7 hari (`find "$BACKUP_DIR" -name "db_*.db" -mtime +7 -delete`).
