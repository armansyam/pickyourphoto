## 🔍 2. Verifikasi Alur Kode Terinci

### A. Autentikasi (`app/api/auth/` & `app/api/admin/auth/`)
- **Rate Limit:** `checkRateLimit()` aktif di login vendor, login admin, dan registrasi — masing-masing **5 percobaan per 60 detik** per IP + email.
- **Role Isolation:** Admin yang mencoba login via `/api/auth/login` ditolak (`403 Forbidden`). Vendor yang mencoba via `/api/admin/auth/login` juga ditolak.
- **JWT:** `getAuthVendor()` di `lib/auth.js` melakukan fresh DB query setiap request (`JOIN vendors v LEFT JOIN plans p ON v.planId = p.id`), memastikan perubahan paket langsung terlihat tanpa logout.
- **Status Blocking:** Akun berstatus `pending`, `suspended`, `expired`, atau status lain di luar `active` **ditolak di `getAuthVendor()`** (baris 56: `if (!freshUser || freshUser.status !== 'active') return null`).

---

### B. Registrasi Vendor (`app/api/auth/register/route.js`)
- Mendukung **dua format input**: `application/json` dan `multipart/form-data`.
- **Blokir paket harga 0:** `if (planDetails.price === 0) return 400` — paket gratis tidak tersedia di registrasi.
- **Blokir WA duplikat:** Cek terhadap vendor `active` atau `pending_payment` lain.
- **Vendor lama re-register (non-active):** Alih-alih insert baru, sistem memperbarui record vendor yang sudah ada (UPDATE statement, bukan INSERT).
- **Bukti Transfer:** Disimpan ke disk di `public/staging_uploads/payment_proofs/`. Ukuran file tidak dikompresi (tidak menggunakan `sharp`).

### D. Alur Import Google Drive & Proxy Gambar

#### Proxy Gambar (`app/api/proxy/thumb/[fileId]/route.js`)
- **Validasi File ID:** Regex `^[a-zA-Z0-9_-]{10,}$` — mencegah path traversal.
- **Fallback:** Jika `lh3.googleusercontent.com` gagal atau bukan `image/*`, fallback ke `drive.google.com/thumbnail`.
- **True Pipe Stream:** `new NextResponse(response.body, ...)` — tidak ada `arrayBuffer()` — RAM server ~0 MB.
- **Cache Header:** `public, max-age=604800, s-maxage=2592000` (CDN 30 hari).

#### Stale Import Recovery (`lib/db.js` startup)
- Proyek dengan status `importing` di-reset ke `failed` saat server booting.

---

### E. Pembersihan Database & Cron (`lib/db.js` setInterval 60 detik)

`setInterval` di `lib/db.js` menjalankan 4 tugas setiap 60 detik:
1. `payment_sessions` kedaluwarsa (`expiresAt < now`) → status `'expired'`.
2. Vendor `pending_payment` yang semua QRIS-nya expired → status `'expired_draft'` (pindah ke sub-tab Arsip).
3. ✅ **Baru (ditambahkan sesi audit ini):** Vendor `active` yang `expiresAt < now` → status `'expired'`, proyek terkait → `'archived'`.
4. Leads `draft_plan` berusia > 48 jam → dihapus permanen.

---

### F. Auto-Backup — KOREKSI PENTING

> ⚠️ **Laporan awal mengklaim Auto-Backup berjalan secara berkala (terjadwal).** Kenyataannya berbeda.

**Kondisi Aktual (dari `app/api/admin/analytics/route.js` baris 183-198):**
- Auto-backup **tidak berjalan sendiri di background secara periodik**.
- Auto-backup ter-trigger **hanya saat Admin membuka halaman Analytics** (GET `/api/admin/analytics`).
- Logika trigger: jika `enable_auto_backup = 1` DAN waktu sekarang dikurangi waktu backup terakhir > `backup_interval_hours`.
- Jika Admin tidak membuka halaman analytics, backup tidak akan pernah berjalan meskipun sudah melewati interval.
- **Catatan Kode Kritis (line 147):** Path database yang dicek di analytics route adalah `path.join(process.cwd(), 'database.db')` (root), sedangkan database sebenarnya ada di `data/database.db` — sehingga `dbSizeBytes` mungkin selalu `0`.

**Dampak:** Admin perlu membuka halaman Analytics setidaknya sesuai interval backup yang dikonfigurasi agar backup berjalan.

---

### G. Alur Seleksi Foto Klien (`app/api/projects/[projectId]/select/route.js`)
- Otorisasi: `accessKey` unik milik klien, dicek per `projectId`.
- Validasi: Semua `photoIds` yang dikirim divalidasi bahwa benar-benar milik proyek tersebut (mencegah injeksi ID asing).
- Batas seleksi: Jika `maxSelection > 0` dan jumlah foto melebihi batas, dikembalikan error `400`.
- Expiry: Jika `expiresAt` proyek sudah lewat, ditolak dengan pesan yang informatif.
- Status proyek otomatis diubah ke `completed` setelah klien submit seleksi.

---

### H. Admin Panel — Vendor Approval (`app/api/admin/vendors/[vendorId]/route.js`)
- **Manual Approve:** Admin bisa set status ke `active` + override `expiresAt`.
- **Auto ExpiresAt:** Jika vendor di-approve ke `active` tanpa tanggal, sistem otomatis mengisi `expiresAt = hari ini + plan.activePeriodDays`.
- **Reset Password:** Admin bisa reset password vendor (min. 6 karakter, di-hash bcrypt cost 10).
- **Email:** Email aktivasi SMTP terkirim otomatis saat status berubah dari non-`active` ke `active`.
- **Delete:** Penghapusan vendor menghapus semua relasi (selections, photos, clients, projects, payment_sessions, subscription_requests) dalam satu transaksi SQLite atomik.
