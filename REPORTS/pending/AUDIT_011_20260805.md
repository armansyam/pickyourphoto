## Penemuan / Issue
- **Tombol aksi masih aktif** saat status vendor `pending_payment`. Klik tombol tidak menghilangkan tampilan, menunjukkan logika UI belum memperbarui kondisi setelah pembayaran selesai.  
- **Penamaan payment method** masih “gabung” di UI; tidak ada pemisahan visual antara QRIS dan manual, sehingga pengguna tidak contek apakah sedang menunggu QRIS atau pembayaran manual.  
- **Webhook Settlement / time‑out** belum terdeteksi; transaksi QRIS sandbox belum menghasilkan webhook, sehingga status tidak berubah menjadi `pending` → `active`/`completed`.  
- **Error internal** pada endpoint `/api/auth/register` terjadi karena validasi payload JSON yang tidak lengkap/format salah – payload harus mencakup `paymentMethod=qris` serta `whatsapp`.  

## Rekomendasi Tindakan
1. **Tangkap webhook** dari Midtrans Sandbox yang mengubah status menjadi `settlement`. Tambahkan handler yang memindahkan `status` ke `active` dan menon-aktifkan tombol aksi.  
2. **Refresh UI** setelah webhook diterima sehingga tombol “Setujui” otomatis hilang.  
3. **Perbaiki validasi payload** di endpoint register, pastikan semua field wajib (`email`, `whatsapp`, `paymentMethod`) dikirim sebagai JSON dengan `Content-Type: application/json`.  
4. **Bersihkan UI** penomoran pemilihan payment; gunakan tab/dropdown terpisah untuk QRIS vs Manual sehingga pengguna tahu kondisi aktuanya.  
5. **Verifikasi kembali** dengan melakukan simulasi QRIS yang berhasil di Sandbox, kemudian pastikan status di DB berubah menjadi `pending_manual` → `active` sebelum melanjutkan ke tahap selanjutnya.
