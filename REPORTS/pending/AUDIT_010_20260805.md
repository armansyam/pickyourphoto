## 2. Analisis Root Cause

### 2.1 Backend Logic (`app/api/auth/register/route.js`)
```javascript
const isGateway = formData.get('paymentMethod') === 'gateway'; // hanya 'gateway' yang true
const initialStatus = isGateway ? 'pending_payment' : 'pending';
```
- User kirim `paymentMethod=gateway` → `isGateway=true` → `initialStatus='pending_payment'`
- **Tapi di DB tersimpan `pending`** — karena logika `UPDATE` tidak include `status` field untuk vendor baru (hanya untuk existing vendor).

### 2.2 Admin Dashboard (`components/admin/AdminVendors.jsx`)
- Filter "Menunggu Konfirmasi" query: `status === 'pending' || status === 'pending_payment'`
- **QRIS vendor ikut masuk filter ini** dan mendapat tombol **"Setujui"** — padahal harusnya **auto-activate via Midtrans webhook**.

### 2.3 Payment Flow
- Endpoint `/api/payment/create` → create Midtrans transaction → save `payment_transactions`
- Endpoint `/api/payment/status` (polling) + `/api/payment/notification` (webhook) → **harusnya auto-update vendor ke `active`**
- **Realita**: Webhook tidak trigger / polling tidak dipanggil → vendor stuck di `pending`.

## 3. Rekomendasi Perbaikan (Untuk Tim Antigravity)

### A. **Backend — Pisahkan Payment Method Enum** (Prioritas: BLOKER)
```sql
-- Migration
ALTER TABLE vendors ADD COLUMN payment_method ENUM('qris', 'manual', 'gateway') DEFAULT 'manual';
ALTER TABLE payment_transactions ADD COLUMN payment_method ENUM('qris', 'manual', 'gateway');
```
Update `register/route.js`:
```javascript
const paymentMethod = formData.get('paymentMethod'); // 'qris' | 'manual' | 'gateway'
const isQris = paymentMethod === 'qris';
const isManual = paymentMethod === 'manual';
const isGateway = paymentMethod === 'gateway'; // legacy support

const initialStatus = isQris ? 'pending_payment' : (isManual ? 'pending_manual' : 'pending');
```

### B. **Backend — Fix Register Status Persist**
Pastikan `INSERT` vendor baru include `status = initialStatus` (sudah benar, tapi verify di DB).

### C. **Frontend — Tambah Tab "QRIS" & "Manual Transfer" di Register Page**
| Tab | Fields | Action |
|-----|--------|--------|
| **QRIS (Otomatis)** | Nama, Email, WA, Password, Paket | Tombol **"Bayar via QRIS"** → call `/api/payment/create` → tampilkan **QR Code Modal** → auto-poll `/api/payment/status` |
| **Transfer Manual** | Nama, Email, WA, Password, Paket, **Upload Bukti** | Tombol **"Kirim Bukti"** → status `pending_manual` → masuk tab "Menunggu Konfirmasi" admin |

### D. **Admin Dashboard — Pisahkan Filter & Hapus Tombol "Setujui" untuk QRIS**
```jsx
// Filter tabs
const tabs = [
  { key: 'pending_qris', label: 'Menunggu Bayar QRIS (Auto)', count },
  { key: 'pending_manual', label: 'Menunggu Verifikasi Manual', count },
  { key: 'active', label: 'User Aktif', count },
  { key: 'expired', label: 'Tidak Aktif / Expired', count },
];

// Hanya tampilkan tombol "Setujui" untuk status === 'pending_manual'
{status === 'pending_manual' && <Button>Setujui</Button>}
```

### E. **Payment Status Polling — Wajib Dipanggil Setelah QRIS**
- Di QR Code Modal: `setInterval(() => checkPaymentStatus(orderId), 3000)`
- Jika `paid: true` → close modal, redirect `/dashboard`, set cookie token.

### F. **Webhook Midtrans — Pastikan Aktif di Sandbox**
- Dashboard Midtrans → Settings → Webhook → URL: `https://pilih.ammang.my.id/api/payment/notification`
- Test dengan "Send Test Notification".
